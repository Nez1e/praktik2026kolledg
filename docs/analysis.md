# Анализ предметной области: AccessEvent

## 1. Сущности и их атрибуты

### 1.1. Пользователь (User)
*   id (уникальный идентификатор)
*   ФИО (полное имя пользователя)
*   email (электронная почта для связи)
*   роль (например, администратор, организатор, участник)
*   статус (активен / заблокирован)

### 1.2. Мероприятие (Event)
*   id (уникальный идентификатор)
*   название (наименование события)
*   описание (краткое описание мероприятия)
*   дата_начала (дата и время начала)
*   дата_окончания (дата и время окончания)
*   место_проведения (адрес или ссылка на онлайн-трансляцию)
*   организатор_id (ссылка на сущность Пользователь)

### 1.3. Билет (Ticket)
*   id (уникальный идентификатор)
*   мероприятие_id (ссылка на событие)
*   тип_билета (например, стандартный, VIP, студенческий)
*   цена (стоимость билета)
*   статус (доступен, продан, забронирован)

### 1.4. Регистрация (Registration)
*   id (уникальный идентификатор)
*   пользователь_id (кто регистрируется)
*   мероприятие_id (на какое событие)
*   дата_регистрации (время создания записи)
*   статус_оплаты (оплачено / не оплачено)

### 1.5. Отзыв (Review)
*   id (уникальный идентификатор)
*   пользователь_id (автор отзыва)
*   мероприятие_id (о каком событии отзыв)
*   текст_отзыва (содержание)
*   оценка (от 1 до 5)

## 2. Бизнес-процессы

1.  Создание мероприятия: Организатор заполняет данные о событии, назначает дату, место и создает типы билетов.
2.  Регистрация на мероприятие: Участник выбирает событие, нажимает «Зарегистрироваться», система создает запись в сущности «Регистрация» и генерирует «Билет».
3.  Оплата билета: Участник оплачивает билет, статус в сущности «Регистрация» меняется на «Оплачено».
4.  Посещение мероприятия: Сканирование билета на входе, проверка статуса регистрации.
5.  Оставление отзыва: После завершения мероприятия участник может оставить отзыв и оценку.
