# Анализ предметной области: AccessEvent

## 1. Описание предметной области
**AccessEvent** — это платформа для организации и проведения мероприятий с особым акцентом на доступность для людей с нарушениями слуха. Система обеспечивает визуальное сопровождение, текстовую коммуникацию и удобную регистрацию участников.

## 2. Сущности и атрибуты

| Сущность | Атрибуты | Описание |
| :--- | :--- | :--- |
| **Event** | id, title, date, location, description, is_inclusive, status | Мероприятие (событие) |
| **Participant** | id, name, email, phone, hearing_status | Участник мероприятия |
| **Organizer** | id, name, contact, rating | Организатор мероприятия |
| **Registration** | id, event_id, participant_id, status, created_at | Заявка на регистрацию |
| **Notification** | id, event_id, type, message, color | Визуальное уведомление |
| **Review** | id, event_id, participant_id, rating, text | Отзыв о мероприятии |
| **Category** | id, name, description | Категория события |
| **Message** | id, event_id, user_id, text, created_at | Сообщение в текстовом чате |

## 3. Бизнес-процессы

### 3.1. Создание мероприятия
Организатор создает мероприятие, указывая дату, место и описание. При необходимости он может отметить событие как инклюзивное (доступное для людей с нарушениями слуха).

### 3.2. Регистрация на мероприятие
Участник находит мероприятие в каталоге и подает заявку на участие. Статус заявки меняется по цепочке: `ожидание` -> `одобрено` / `отклонено`.

### 3.3. Визуальное уведомление (оповещение)
Система автоматически отправляет визуальные уведомления участникам. За 30 минут до начала мероприятия отображается цветной баннер:
* **Зеленый** — мероприятие началось.
* **Желтый** — мероприятие скоро начнется.
* **Красный** — мероприятие отменено.
*Уведомления также могут быть привязаны к изменению статуса события организатором.*

### 3.4. Текстовый чат
Внутри страницы мероприятия реализован текстовый чат. Участники могут писать сообщения, а организатор — отвечать на них в реальном времени.

### 3.5. Отзыв на мероприятие
После завершения события участник может оставить отзыв, включающий числовую оценку и текстовый комментарий.

## 4. Роли пользователей
* **Организатор** — создает мероприятия и управляет ими.
* **Участник** — регистрируется на мероприятия и посещает их.
* **Администратор** — контролирует работу платформы и модерирует контент.
* **Гость** — просматривает список мероприятий без регистрации.
